Gimp 3.0.4 C++ plug-ins how to position text in a BusyBox widget to be at the top and left inside the widget

o4-mini:
In GIMP-3 the BusyBox is really just a little convenience widget around a spinner plus a GtkLabel inside a GtkBox (or—in GTK4 terms—a GtkOverlay + GtkBox).  By default everything is centered, but you can override that both in code (by tweaking the halign/valign of the box or its label) or with a tiny bit of CSS.

Here are two approaches:

1)  “Pure C++” approach: grab the internal label and set its halign/valign  
2)  CSS approach: add a style-class to your BusyBox and write a few lines of CSS  

— -----------------------------------------------------------------------

## 1) Pure C++ approach

Assuming you’ve got a `Gimp::Widgets::BusyBox` called `busy`:

```cpp
// 1) force the BusyBox itself to pack its children at the top/left
busy.set_halign(Gtk::Align::START);
busy.set_valign(Gtk::Align::START);

// 2) give it a little padding so it isn't flush against the frame
busy.set_margin_start(4);
busy.set_margin_top(4);

// 3) fetch the internal label widget and left-align it
//    (unfortunately the C++ wrapper doesn't expose it in the header,
//     so we go via the underlying GtkWidget* and downcast)
if (auto *w = GTK_WIDGET (busy.gobj())) {
  // find the label in the BusyBox’s children
  GList *kids = gtk_container_get_children(GTK_CONTAINER(w));
  for (GList *l = kids; l; l = l->next)
  {
    if (GTK_IS_LABEL(l->data))
    {
      GtkLabel *lbl = GTK_LABEL(l->data);
      // make it top/left
      gtk_widget_set_halign(GTK_WIDGET(lbl), GTK_ALIGN_START);
      gtk_widget_set_valign(GTK_WIDGET(lbl), GTK_ALIGN_START);
      gtk_label_set_xalign(lbl, 0.0f);  // left text
      gtk_label_set_yalign(lbl, 0.0f);  // top line
      break;
    }
  }
  g_list_free(kids);
}
```

That handful of calls will force both the _container_ and the _label_ to pack at START/START (i.e. top-left).

— -----------------------------------------------------------------------

## 2) CSS approach

If you’d rather keep your C++ super‐clean, you can do it all in CSS.  

In your C++:

```cpp
busy.add_css_class("my-busy-top-left");
busy.set_text("Working… please wait");
```

Then in your plugin’s CSS file (e.g. `my-plugin.css`, loaded into your GtkCssProvider):

```css
/* make the BusyBox’s internal box pack at the start */
.my-busy-top-left {
  /* in GTK4 these properties live on the parent container */
  justify-content: start;  /* main axis = horizontal for a GtkBox */
  align-items: start;      /* cross axis = vertical */
  padding-start: 4px;      /* a smidge of margin */
  padding-top:   4px;
}

/* left-align the label inside it */
.my-busy-top-left label {
  text-align: start;
  justify-self: start;
  align-self:   start;
}
```

Then make sure you install that CSS in your plugin before you create the BusyBox:

```cpp
auto css = Gtk::CssProvider::create();
css->load_from_file("my-plugin.css");
Gtk::StyleContext::add_provider_for_display(
  Gdk::Display::get_default(),
  css,
  GTK_STYLE_PROVIDER_PRIORITY_APPLICATION);
```

Now any `Gimp::Widgets::BusyBox` you give the `.my-busy-top-left` style class will pack its spinner+text at the top‐left.

— -----------------------------------------------------------------------

Pick whichever style you prefer.  In both cases you end up with your BusyBox’s label sitting snug in the top-left corner of the widget rather than dead center.

Here’s a minimal C example showing how you can use  
gimp_adaptive_supersample_area() (GIMP-3.0.4) to:

 1. Read a rectangular block of pixels from a source drawable into a  
    linear double‐array (RGBA interleaved)  
 2. (Optionally) do something to those pixels in your array  
 3. Write them back into a second drawable

——————————————————————————————————————————————  

```c
#include <libgimp/gimp.h>

/* 
 * Read from “src_drawable” into a gdouble array rgba[], one double
 * per channel, four channels per pixel (R, G, B, A).
 *
 * Then write rgba[] back into “dst_drawable” at the same coords.
 */
static void
example_adaptive_supersample (GimpDrawable *src_drawable,
                             GimpDrawable *dst_drawable,
                             gint            x,
                             gint            y,
                             gint            width,
                             gint            height)
{
  const gint      n_pixels = width * height;
  /* 4 channels per pixel */
  gdouble        *rgba      = g_new (gdouble, n_pixels * 4);
  gboolean        success;
  gint            radius    = 1;

  /* --------------------------------------------------
   * STEP 1: Read the block from src_drawable
   * -------------------------------------------------- */
  /* NOTE: We use scale_x=scale_y=1.0 → a 1:1 read.
   * preserve_aspect = FALSE, sample method = ADAPTIVE,
   * chroma consideration = OFF, clamp = TRUE.
   *
   * The last parameter is our output gdouble array.
   */
  success = gimp_adaptive_supersample_area (
      src_drawable,
      x, y, width, height,
      /* x_scale */ 1.0,
      /* y_scale */ 1.0,
      /* preserve_aspect */ FALSE,
      /* sample_method */ GIMP_PIXEL_SAMPLE_ADAPTIVE,
      /* chroma_consideration */ GIMP_PIXEL_SAMPLE_CHROMA_OFF,
      /* radius */ radius,
      /* clamp */ TRUE,
      /* out_pixels */ rgba);

  if (!success)
  {
    g_warning ("gimp_adaptive_supersample_area() read failed");
    goto CLEANUP;
  }

  /* --------------------------------------------------
   * STEP 2: (optional) process your rgba[] here …
   * e.g. invert colors, apply filter, etc.
   * -------------------------------------------------- */
  for (gint i = 0; i < n_pixels; i++)
  {
    /* invert RGB, leave A alone */
    rgba[4*i + 0] = 1.0 - rgba[4*i + 0];
    rgba[4*i + 1] = 1.0 - rgba[4*i + 1];
    rgba[4*i + 2] = 1.0 - rgba[4*i + 2];
  }

  /* --------------------------------------------------
   * STEP 3: Write it back into dst_drawable
   * (again at 1:1, so scale=1.0)
   * -------------------------------------------------- */
  success = gimp_adaptive_supersample_area (
      dst_drawable,
      x, y, width, height,
      /* x_scale */ 1.0,
      /* y_scale */ 1.0,
      /* preserve_aspect */ FALSE,
      /* sample_method */ GIMP_PIXEL_SAMPLE_ADAPTIVE,
      /* chroma_consideration */ GIMP_PIXEL_SAMPLE_CHROMA_OFF,
      /* radius */ radius,
      /* clamp */ TRUE,
      /* in_pixels */ rgba);

  if (!success)
    g_warning ("gimp_adaptive_supersample_area() write failed");

CLEANUP:
  g_free (rgba);
}
```

How this works:

• You allocate an array of `gdouble` of size `width*height*4`.  
• You call `gimp_adaptive_supersample_area()` once to *read* into that array.  
• You do whatever processing you like on the linear RGBA data.  
• You call `gimp_adaptive_supersample_area()` again to *write* from that array  
  back into another drawable.  

Notes:

– The function returns gboolean for success/failure.  
– The parameters `scale_x` / `scale_y` control up/down‐sampling—you can  
  use them to sample at higher‐resolution or smaller. For a direct copy, use 1.0.  
– `GIMP_PIXEL_SAMPLE_ADAPTIVE` is the “supersample” algorithm. You can swap  
  in any other `GimpPixelSampleMethod` if you prefer.  
– `radius` only matters for filters that look at neighbors; a value of 1 is usually fine.  
– `clamp = TRUE` ensures your doubles stay within [0,1].

You can wrap this in your GIMP plug-in’s run() function, lock the relevant regions  
with `gimp_drawable_mask_bounds()`, call `gimp_drawable_detach()`, flush and merge  
the update on the destination, etc. But the heart of the pixel I/O is exactly  
the pair of calls to `gimp_adaptive_supersample_area()`.

Below is a minimal‐working example of how you might call the GTK-3.0 / GIMP-3.0 version of  
gimp_adaptive_supersample_area() with your own “render” and “put‐pixel” callbacks.  In this case we’ll  
simply use supersampling to copy a rectangular block of pixels from one drawable to another — but it shows  
how to wire up your render_func, put_pixel_func and progress_func.  

```c
#include <libgimp/gimp.h>

/* --------------------------------------------------
 * STEP 0: define the signatures from the docs
 *
 * gulong
 * gimp_adaptive_supersample_area (
 *   gint                x1,
 *   gint                y1,
 *   gint                x2,
 *   gint                y2,
 *   gint                max_depth,
 *   gdouble             threshold,
 *   GimpRenderFunc      render_func,
 *   gpointer            render_data,
 *   GimpPutPixelFunc    put_pixel_func,
 *   gpointer            put_pixel_data,
 *   GimpProgressFunc    progress_func,
 *   gpointer            progress_data
 * );
 *
 * typedef void (*GimpRenderFunc) (
 *   gdouble    x,
 *   gdouble    y,
 *   gdouble   *pixel,       // out: RGBA in [0,1]
 *   gpointer   data
 * );
 *
 * typedef void (*GimpPutPixelFunc) (
 *   gint       x,
 *   gint       y,
 *   gdouble   *pixel,       // in: RGBA in [0,1]
 *   gpointer   data
 * );
 *
 * typedef void (*GimpProgressFunc) (
 *   gdouble    progress,    // 0.0–1.0
 *   gpointer   data
 * );
 * --------------------------------------------------*/

/* A little context for both callbacks */
typedef struct
{
  GimpDrawable    *src_drawable;
  GimpDrawable    *dst_drawable;
  GimpPixelRgn     src_rgn;
  GimpPixelRgn     dst_rgn;
  gint             bpp;          /* bytes/chunk, e.g. 4 for RGBA8 */
} SupersampleCtx;

/* This render_func is called at each sample point (x,y) in DOUBLE coords.
 * Here we simply round to nearest integer and grab that pixel from src_rgn
 * and convert it into four doubles in [0,1].
 */
static void
my_render_func (gdouble    x,
                gdouble    y,
                gdouble   *out_pixel,    /* must write out_pixel[0..3] */
                gpointer   data)
{
  SupersampleCtx *ctx = (SupersampleCtx*) data;
  gint ix = CLAMP ((gint) (x + 0.5),  ctx->src_rgn.x1,
                                    ctx->src_rgn.x2 - 1);
  gint iy = CLAMP ((gint) (y + 0.5),  ctx->src_rgn.y1,
                                    ctx->src_rgn.y2 - 1);

  /* read raw bytes from the src region */
  guchar raw[4] = {0,0,0,255};
  gimp_pixel_rgn_get_pixel (&ctx->src_rgn, raw, ix, iy);

  /* convert to double */
  out_pixel[0] = raw[0] / 255.0;
  out_pixel[1] = raw[1] / 255.0;
  out_pixel[2] = raw[2] / 255.0;
  out_pixel[3] = raw[3] / 255.0;
}

/* This put_pixel_func is called once supersampling has decided
 * on a final RGBA value for pixel (x,y).  We convert back to bytes
 * and write into the dst_rgn.
 */
static void
my_put_pixel_func (gint       x,
                   gint       y,
                   gdouble   *in_pixel,     /* RGBA doubles */
                   gpointer   data)
{
  SupersampleCtx *ctx = (SupersampleCtx*) data;
  guchar raw[4];

  raw[0] = CLAMP ((gint) (in_pixel[0] * 255.0 + 0.5), 0, 255);
  raw[1] = CLAMP ((gint) (in_pixel[1] * 255.0 + 0.5), 0, 255);
  raw[2] = CLAMP ((gint) (in_pixel[2] * 255.0 + 0.5), 0, 255);
  raw[3] = CLAMP ((gint) (in_pixel[3] * 255.0 + 0.5), 0, 255);

  gimp_pixel_rgn_set_pixel (&ctx->dst_rgn, raw, x, y);
}

/* A trivial progress function: here you could pump a GimpProgress object */
static void
my_progress_func (gdouble  progress,
                  gpointer data)
{
  /* fprintf (stderr, "Progress: %3.1f%%\n", progress * 100.0); */
  /* or gimp_progress_update (progress), etc. */
}

/* --------------------------------------------------
 * Example driver: copy a block (x1,y1)-(x2,y2) from src to dst
 * using adaptive supersampling.
 * --------------------------------------------------*/
void
do_adaptive_copy (GimpDrawable *src_drawable,
                  GimpDrawable *dst_drawable,
                  gint           x1,
                  gint           y1,
                  gint           x2,
                  gint           y2)
{
  SupersampleCtx ctx;

  /* initialize context */
  ctx.src_drawable = src_drawable;
  ctx.dst_drawable = dst_drawable;
  ctx.bpp = gimp_drawable_bpp (dst_drawable->drawable_id);

  /* lock & init pixel regions */
  gimp_pixel_rgn_init (&ctx.src_rgn,
                       src_drawable,
                       x1, y1,            /* origin */
                       x2 - x1, y2 - y1,  /* size */
                       FALSE,             /* do not shadow */
                       FALSE);            /* read-only */

  gimp_pixel_rgn_init (&ctx.dst_rgn,
                       dst_drawable,
                       x1, y1,
                       x2 - x1, y2 - y1,
                       TRUE,              /* shadow (we will write) */
                       TRUE);             /* has shadow */

  /* call the supersampler:
   *
   *   max_depth = 5         ← how deep recursion in adaptive subdivision
   *   threshold = 0.02      ← when to stop subdividing L/R/G/B diff < thr
   */
  gulong num_done = gimp_adaptive_supersample_area (
      x1, y1, x2, y2,
      /* max_depth */   5,
      /* threshold */   0.02,
      /* render_func */ my_render_func,
      /* render_data */ &ctx,
      /* put_pixel */   my_put_pixel_func,
      /* put_data */    &ctx,
      /* progress */    my_progress_func,
      /* prog_data */   NULL);

  g_debug ("adaptive supersample did %lu pixels\n", num_done);

  /* flush & merge back the dst region */
  gimp_drawable_flush (dst_drawable);
  gimp_drawable_merge_shadow (dst_drawable->drawable_id, TRUE);
  gimp_drawable_update (dst_drawable->drawable_id,
                        x1, y1, x2 - x1, y2 - y1);
}
```

How it hangs together:

1) You fill out a little context struct that holds both source and destination drawables  
   (and their pixel regions).  
2) You provide `my_render_func()`, which is called with floating‐point sample coordinates.  
   Here we simply round to integer and fetch the nearest pixel from the source.  
3) You provide `my_put_pixel_func()`, which GIMP calls once the adaptive sampler  
   has decided on a final RGBA for each integer pixel.  We immediately write that  
   color into the destination pixel region.  
4) A `my_progress_func()` can be used to drive a progress bar.  
5) Finally you call `gimp_adaptive_supersample_area()`, passing your callbacks  
   plus a `max_depth` and `threshold` that control how aggressively it subdivides.  

That should get you up and running.  From here you can replace the render function with  
any ray‐tracer, fractal evaluator or real filter kernel you like, and use supersample to  
produce anti‐aliased / smoothed output.
