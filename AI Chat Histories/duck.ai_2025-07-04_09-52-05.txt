Using clang++ compiler, how do I create a c++ static library intended to be imported by clang++ in another c++ application, with the static library statically linking other libraries and also using the "-static" flag, so that the static library I create includes the libraries I statically link and are available to the c++ program I later create, so that the end-result c++ program doesn't need to link or include any of those other libraries?  I'm using Codeblocks IDE on Windows 11, and MSYS2 clang compiler toolchain.

o4-mini:
Below is a step-by-step recipe (MSYS2/Clang on Win11, Code::Blocks or CLI) for building

  1. A `.a`-style static library of your own code,  
  2. “Embedding” (merging) other `.a`-style static libraries into it,  
  3. Producing a final executable which only needs `-lmylib.a` and **no** other libs.

—————————————————————————————————————————————————
1) Compile your own sources to object files  
————————————————————————————————————————————————

Suppose your library sources live in  src/ :

    cd project/src
    clang++ -O2 -std=c++17 -c foo.cpp -o foo.o
    clang++ -O2 -std=c++17 -c bar.cpp -o bar.o

You now have foo.o, bar.o.

————————————————————————————————————————————————
2) Pull in (“merge”) external static libraries  
————————————————————————————————————————————————

Let’s say you want to bundle libext1.a and libext2.a (from somewhere on your system) into your final libmylib.a so that the end-user never has to think about them.

  • Copy or symlink the external .a files next to your .o files:  
      cp /path/to/libext1.a /path/to/libext2.a .

  • Extract their object files:  
      ar x libext1.a  
      ar x libext2.a  

    This produces a bunch of `.o` files in your folder.

————————————————————————————————————————————————
3) Create your “fat” static library  
————————————————————————————————————————————————

Now pack *all* the .o files (yours + the extracted ones) into one archive:

    ar rcs libmylib.a *.o

You now have `libmylib.a` containing:

  • foo.o, bar.o  (your code)  
  • ext1_*.o      (from libext1.a)  
  • ext2_*.o      (from libext2.a)  

No need for the original libext1.a / libext2.a any more when linking.

————————————————————————————————————————————————
4) Link your final executable  
————————————————————————————————————————————————

In your application project, simply do:

    clang++ -static \
            -static-libgcc -static-libstdc++ \
            main.cpp \
            -L/path/to/your/libmylib/folder \
            -lmylib \
            -o myprogram.exe

Explanation of flags:

  • `-static`  
    Force static linking of all system libraries.  
  • `-static-libgcc -static-libstdc++`  
    Statically link libgcc and libstdc++ (avoid pulling in DLLs).  
  • `-L… -lmylib`  
    Point to your combined static archive.  

Because you already merged ext1/ext2 into `libmylib.a`, you do *not* need to add `-lext1 -lext2` on the link line.  

————————————————————————————————————————————————
5) (Optional) Integrate into Code::Blocks  
————————————————————————————————————————————————

  1. In your library project’s “Build options…”, set the custom build steps  
     so that after compiling your `.o` files it runs the `ar x … && ar rcs …` sequence.  
  2. In your application project’s “Linker settings”, add the path to `libmylib.a`  
     (as a “Link library”) and set the additional linker flags  
     `-static -static-libgcc -static-libstdc++`.  

That’s it!  
Your final `myprogram.exe` will contain  
  • your code  
  • ext1 + ext2  
  • C++ runtime, libgcc  
all fully static, so users of `myprogram.exe` never have to install or link anything else.
