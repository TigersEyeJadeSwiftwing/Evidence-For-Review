### 1. Precompute masks, avoid repeated shifts  
Compute the two masks—one for the high 64 bits, one for the low—upfront in lookup tables indexed by `j0`. This turns all your shifts into table loads.

```cpp

static const uint64_t high_mask[64] = { /* (0x0000ffffffffffffULL)>>j0 for j0=0..47, else 0 */ };
static const uint64_t low_mask[64]  = { /* -(1ULL)>>(j0-48) for j0=48..111, else 0 */ };

static inline __attribute__((always_inline, hot))
__float128 floorq_fast(__float128 x) {
    int64_t i0, i1, j0;
    GET_FLT128_WORDS64(i0, i1, x);
    j0 = ((i0 >> 48) & 0x7fff) - 0x3fff;

    if (j0 < 0) {
        // |x| < 1
        if (i0 < 0 && ( (i0 & 0x7fffffffffffffffLL) | i1) != 0) {
            i0 = 0xbfff000000000000ULL; i1 = 0;
        } else {
            i0 = i1 = 0;
        }
    }
    else if (j0 < 48) {
        uint64_t m = high_mask[j0];
        if (((i0 & m) | i1) != 0) {
            if (i0 < 0)
                i0 += (0x0001000000000000LL) >> j0;
            i0 &= ~m;
            i1 = 0;
        }
    }
    else if (j0 <= 111) {
        uint64_t m = low_mask[j0 - 48];
        if ((i1 & m) != 0) {
            if (i0 < 0) {
                if (j0 == 48) i0 += 1;
                else {
                    uint64_t carry = i1 + (1ULL << (112 - j0));
                    if (carry < i1) i0 += 1;
                    i1 = carry;
                }
            }
            i1 &= ~m;
        }
    }
    // j0 >111: x is already integral, NaN or ±Inf
    SET_FLT128_WORDS64(x, i0, i1);
    return x;
}
```

Benefits:  
- Eliminates per-call shifts.  
- Reduces branch mispredictions by simplifying conditions.

**Yes. You can replace all the bit-twiddling with a “magic offset” trick using pure floating-point arithmetic.** By adding and then subtracting a large power of two, you force the fractional part to drop out.

## 🚀 Magic-Number Floor for __float128  

All we need is a constant  
```cpp
static const __float128 TWO_POW_113 = ((__float128)1) * ( (__float128)1 << 113 );
```  
(Quad-precision has a 112-bit significand, so 2ⁱ³ strips off all fractions.)  

Then implement `floorq` like this:  
```cpp
static inline __attribute__((always_inline, hot))
__float128 floorq(__float128 x) {
    if (__builtin_isnanq(x) || __builtin_isinfq(x)) 
        return x;                // Preserve NaN and ±Inf

    // For very large |x|, x is already integral
    if (fabsl(x) >= TWO_POW_113)   
        return x;                

    __float128 y;
    if (x >= 0) {
        y = x + TWO_POW_113;      // shift fractional bits out
        y = y - TWO_POW_113;
        // y is truncated toward zero → same as floor for x ≥ 0
        return y;
    } else {
        // For negatives, truncation gives ceil. To get floor, subtract 1. 
        y = x - TWO_POW_113;
        y = y + TWO_POW_113;
        if (y == x)
            return y;             // already integral
        else
            return y - 1;         // step down
    }
}
```  

### Why this is faster  
- **No integer extracts, masks, or branches per bit**: just two adds, two subtracts, one comparison.  
- Leverages the FPU’s hardware rounding-to-zero for the strip-off.  
- Only 1 or 2 branches (NaN/Inf check and sign).  

<hr>  

## ⚠️ Caveats and ranges  

- Valid for all **finite** `x` with |x| < 2¹¹³. Beyond that, the result is already integral in quad precision.  
- Handles negative values correctly by an extra `-1` when truncation didn’t change an already non-integral `x`.  
- Preserves NaNs and infinities explicitly.  

This approach typically compiles down to a handful of FPU instructions, beating any manual bit-twiddle sequence.

## 🌟 ceilq(__float128 x) Implementation

```cpp
static inline __attribute__((always_inline, hot))
__float128 ceilq(__float128 x) {
    // Preserve NaN and ±Inf
    if (__builtin_isnanq(x) || __builtin_isinfq(x))
        return x;

    // Magic constant: 2^113 for quad-precision
    const __float128 B = ((__float128)1) * ( (__float128)1 << 113 );

    // For very large |x|, x is already integral
    if (fabsl(x) >= B)
        return x;

    __float128 y;
    if (x > 0) {
        // Truncate toward zero yields floor for positive x
        y = x + B;
        y = y - B;
        // If there was any fractional part, bump up
        return (y == x) ? y : (y + 1);
    } else {
        // For negative x, truncation toward zero = ceil
        y = x - B;
        y = y + B;
        return y;
    }
}
```

<hr>

### How it works

- **Magic offset (B = 2¹¹³)** shifts the significand so the hardware truncates off the fraction.  
- For **x > 0**, truncation gives ⌊x⌋. If `y != x`, we add 1 to get ⌈x⌉.  
- For **x < 0**, truncation gives ⌈x⌉ directly, so no extra step is needed.  
- NaNs, infinities, and very large values (|x| ≥ 2¹¹³) are returned unchanged.
